# Lane 3 — Tubs list + one tub Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build screens 4 (Tubs) and 5 (One tub) of the app rebuild, plus Add tub, and retire `/p/[id]`.

**Architecture:** Pure history helpers (`src/lib/tub-history.ts`) and pure view-model builders (`src/components/tub/*.ts`) hold every rule and are unit-tested. They are kept apart from the server pages, which only load rows and render. Pages under `src/app/tubs/` are dynamic server components behind `getCurrentMembership()`. Add tub is a server action in `src/app/tubs/new/actions.ts`. Start visit calls Lane 2's `startVisit`.

**Tech Stack:** Next.js 16.3 App Router (RSC + server actions), React 19, TypeScript strict, Supabase JS, Vitest + Testing Library (jsdom).

**Spec:** `docs/superpowers/specs/2026-10-27-app-rebuild-design.md` (screens 4, 5). Parent plan: `docs/superpowers/plans/2026-10-27-app-rebuild.md` (Lane 3). Mockup: `tracktub-vault/40 Brand/App mockup 2026-10/Tubs.dc.html`, `Tub.dc.html`.

## Global Constraints

- All of the parent plan's Global Constraints apply: worktree → PR → green `web (lint · typecheck · build)` + `rls` → squash-merge. Never touch `supabase/migrations/` or `src/lib/supabase/types.ts`. Never edit `AppShell`/`TabBar`/`app-tokens.css`.
- Copy (D23): never "verified", "tamper-proof", "dispute-grade", "immutable".
- Green (`--tt-ok`) only for locked / in-range. Amber (`--tt-due`, text `--tt-due-text`) for due / out of range.
- Signed-in pages stay dynamic: every page calls `getCurrentMembership()` (cookies) first.
- Care defaults from `CARE_DEFAULTS` (drain 90, filter 60) when `property.*_interval_days` is null.
- "Due soon" window: 7 days. This matches Lane 5's Needs attention rule.
- Empty values render as "—". The no-history log reads "No visits yet". Never NaN or "Invalid Date".
- Tap targets ≥ 44px; styling via `--tt-*` tokens (inline styles, as the shell does).

## Review Focus

1. **A tub with no visits at all:** the brief tiles show "—", the list says "No visits yet", the dot is neutral, and Start visit shows. Tests: `tub-history` `no visits`; `buildBrief` `no visits`; `TubBrief` render `no visits` (Tasks 1, 3, 4).
2. **A visit whose reading has some rows unset (null):** a null found value is never counted as out of range and breaks a streak; it renders "—", never "null"/"NaN". Tests: `foundStreak` `null breaks the streak`; `visitHeadline` `unset rows` (Tasks 1, 3).
3. **Bad or future timestamps** (clock skew, a string that isn't a date): `daysSince` returns null for an invalid Date and 0 for a future one. Tests: `daysSince` `invalid date → null`, `future → 0` (Task 1).
4. **Tubs with no client (`client_id` null):** they are listed under "No client" rather than dropped. Test: `groupTubsByClient` `null client` (Task 2).
5. **A tub id that isn't the caller's, or isn't a uuid:** `/tubs/[id]` returns `notFound()` (RLS returns no row), never a crash. Covered by `property` select `.maybeSingle()` + `notFound()` in Task 4; checked manually on the preview.

**Files:**

**Interfaces — Produces:**

```ts
export type HistoryVisit = {
  at: Date; // visit start (turnover.submitted_at_server)
  cleaningSteps: readonly string[]; // turnover.cleaning_steps
  found: Partial<Record<ReadingField, number | null>> | null; // as-found reading, null when none
};
export function lastStepDate(
  visits: readonly HistoryVisit[],
  code: CleaningStepCode,
): Date | null;
export function foundStreak(
  visits: readonly HistoryVisit[],
  field: ReadingField,
): number;
export function daysSince(d: Date | null, now: Date): number | null;
```

- Order-independent: both list functions sort by `at`, newest first, internally.
- `foundStreak` counts from the newest visit back while `inRange(field, value) === false`. A missing or null value stops the count, so a streak is never claimed for a reading nobody took.
- `daysSince` = `Math.floor((now − d) / 86_400_000)`, clamped to ≥ 0. Returns null for a null or invalid Date.

```ts
  tub: TubCareInput;
  visits: readonly HistoryVisit[];
  lastVisitOpened: boolean | null;
  now: Date;
}): BriefTile[]; // exactly 4, in spec order
// log.ts
export type LogPhoto = {
  phase: "before" | "after";
  slot: string;
  capturedAt: Date | null;
};
export type LogVisit = HistoryVisit & {
  id: string;
  status: "draft" | "submitted_locked";
  left: Partial<Record<ReadingField, number | null>> | null;
  foundAt: Date | null;
  leftAt: Date | null;
  treatments: readonly string[];
  photos: readonly LogPhoto[];
};
export function visitEnd(v: LogVisit): Date | null; // latest of photo capturedAt / foundAt / leftAt
export function isPartial(v: LogVisit): boolean; // no found reading OR no photo at all
export function visitHeadline(v: LogVisit): string; // "Found pH 7.9 · left 7.5 · Cleaned filter · 3 photos"
export type DraftEntry = {
  at: Date | null;
  kind: "photo" | "reading" | "work";
  title: string;
  chips?: { text: string; out: boolean }[];
};
export function draftEntries(v: LogVisit): DraftEntry[]; // oldest first; untimed work last
export function stillToLog(v: LogVisit): string[]; // e.g. ["Reading as left", "after photos"]
```

- Brief tiles (copy from the mockup):
  1. `{n}d` / "Since drain" / "Usually every {interval}". Due tone when `inDays ≤ 7`.
  2. last found pH (1 decimal) / "pH on arrival" / "High {n} visits running" or "Low …" when `foundStreak ≥ 2`, else "Target 7.2–7.8". Due tone when out of range.
  3. `{n}d` / "On this filter" / "Usually every {interval}" (days since the last `filter_replaced`). Due tone when due.
  4. `{n}d` / "Since last visit" / "Record opened by owner" | "Not opened yet" | "" (null = no share link).
  - With no data, the value is "—".
- `visitHeadline`: found part = out-of-range found fields ("Found pH 7.9, Alk 70"), or "Found in range", or "No reading". Left part = "left all in range" / "left pH 7.5" / omitted. Then work labels from `CLEANING_STEPS`, then "{n} photo(s)". Joined with " · ". Null rows are skipped, never printed.
- `stillToLog` checks, in order: "Before photo" (no before photo), "Reading as found" (no found values), "Work" (no cleaning steps and no treatments), "Reading as left" (no left values), "After photos" (missing after `full_frame` or after `cover`).
- `isPartial`: no found reading or no photo (spec §6: "missing a reading or a photo").
